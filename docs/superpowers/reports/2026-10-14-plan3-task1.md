## Consumable interfaces

- `PublicationID = UUID`; `PublicationState`: queued/capturing/uploading/verifying/completed/cancelled/failed.
- `PublicationSource(manager: DatabaseManager, snapshotDirectory: URL, scope: any PublicationScopeAccess = SecurityScopedPublicationAccess())`. Caller supplies app-local durable support directory; tests supply disposable directories. `capture(trackID:destinationRelativePath:confirmedOutsideRootCopy: Bool = false) async throws -> PublicationID`. Two-argument form works for inside-root sources and retains exact relative path. Outside-root copy requires explicit confirmed bool. Destination subdirectories must already exist; no implicit rename or directory creation.
- `PublicationSource.journal` exposes `record(UUID)`, `all()`, `save(Publication)` and `recoverInterruptedCaptures()`. Static `PublicationJournal.record(_:in:)` / `save(_:in:)` operate in caller's GRDB transaction for Task3 mapping+completion atomicity; no nested writes. Task2 updates upload session/state using read-modify-save. `PublicationUploadSession(id: String, offset: UInt64)`; offset bounded to snapshot size. `PublicationRemoteProof(fileID: String, contentHash: String, size: UInt64)` checks Dropbox ID/hash/size. Persist only provider operation/session identity, never tokens.
- `Publication` fields: id/trackID/generation (initial 1)/snapshot/destination/state/uploadSession/verifiedMapping/error. `PublicationSnapshot`: original DB ID/path/bookmark, pinned `SyncPairing`, sourceIdentity, snapshotPath, sha256, dropboxHash, pairedIdentity. `isReady` gates uploadable states. Snapshot identity immutable once ready; original binding immutable throughout. State completion requires verified proof.
- `verifySnapshot(record)` checks snapshot SHA256/Dropbox content hash/size without whole-file allocation. `verifySourceAndCopy(record)` also resolves/holds scope, checks current DB path/pairing and source/copy stat+hash before and after reads. Task2 must call snapshot verification before upload; Task3 must call source/copy verification before mapping reuse/completion. Existing mapping owner still owns remote metadata validation.
- `PublicationScopeAccess.access(bookmark:expectedPath:) -> PublicationScopeLease` is the test port. Production rejects stale/unresolvable bookmark, changed binding and failed scope access. Lease stays alive throughout capture. Source comes exclusively from tracks JOIN folders existing bookmark; root exclusively persisted pairing bookmark.
- Error enum persists sanitized categories only: invalidDestination/unavailableSource/unavailableScope/sourceChanged/needsConfirmation/needsNewName/integrity/invalidTransition/storage.

## Safety and durability

Appends v15 schema exactly through shared_music_publication table. Capturing row commits before file capture; queued row only follows independent stable source re-read, source DB/pairing revalidation, immutable snapshot hash, verified paired copy and final source/copy verification. Original rows/memberships/bytes untouched. UUID snapshot files are operation-owned; crash recovery marks capturing as failed and never deletes originals or paired copies. Incomplete snapshots are retained rather than unsafe broad cleanup.

All destination components reject absolute/traversal/empty/reserved `.crate-sync` case-insensitive paths before effects. Descriptor-based O_NOFOLLOW traversal pins every component of scope root/source/destination; symlinks fail closed. Outside copy streams to exclusive same-directory stage, fsyncs it, atomically links without overwrite, independently hashes exact destination, removes only owned stage and fsyncs parent. Equal bytes reuse existing copy; different bytes return needsNewName. No overwrite/autorename. 64KiB streaming SHA256 plus 4MiB Dropbox hash boundaries works across short reads. Source identity includes device/inode/size/mtime/ctime; hash/stat/path/pairing checked again. Snapshot file chmod read-only, fsync file and directory before ready.
